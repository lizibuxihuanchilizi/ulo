# ULO · 让猫厕所「看见」猫咪

Prism 项目组题目 · **选项 B（直接动手）** 的交付物：一个纯前端、零依赖、可以发链接给别人用手机直接打开的交互式 Demo。

题目要求的三件事，这里都用可交互的方式跑通了：

| 题目要求 | Demo 里的实现 |
| --- | --- |
| 分辨是哪只猫 | 重量特征 + 图像特征加权打分，输出置信度与打分明细；证据矛盾时**拒绝下结论** |
| 记录如厕行为 | 每条记录含时长、排出量、排尿/排便判定、重量曲线，可按猫与异常级别筛选 |
| 发现健康异常 | 6 条规则的个体化预警引擎：体重下降、排尿频繁、久蹲、尿量偏少、长时间无记录、粪便量偏离 |
| 重力感应 + 图像识别 | 模拟器实时演出完整的称重事件序列 + 摄像头抓拍帧，算法真实运行在浏览器里 |

> ⚠️ 所有猫咪、记录都是脚本生成的**合成数据**，仅用于演示，**不构成任何医疗建议**。

## 一、怎么体验（初代版本）

### 方式 1：本地直接打开（最快）
双击 `index.html` 即可。不需要装任何东西、不需要联网。

> 注：以 `file://` 打开时，浏览器会认为 SVG 图片"污染"了画布，图像特征会退化成确定性模拟向量（页面底部会明确标注当前用的是哪种）。功能不受影响。

### 方式 2：本地起一个静态服务（更接近线上环境）
```bash
# 本机已装 Node，任选一条
npx serve .          # 或者
node -e "const h=require('http'),f=require('fs'),p=require('path');h.createServer((q,s)=>{let u=q.url.split('?')[0];if(u==='/')u='/index.html';const t=p.join(process.cwd(),u);if(!f.existsSync(t)){s.writeHead(404);return s.end()}s.writeHead(200,{'Content-Type':{'.html':'text/html;charset=utf-8','.js':'text/javascript;charset=utf-8','.css':'text/css;charset=utf-8','.svg':'image/svg+xml'}[p.extname(t)]||'application/octet-stream'});f.createReadStream(t).pipe(s)}).listen(8123)"
```
然后打开 `http://localhost:8123`。走 http 时 canvas 可以正常读取像素，图像特征会走**真实提取**。

### 建议的体验顺序
1. **看板** —— 一进来就能看到团子同时触发了体重下降、排尿频繁、久蹲、尿量偏少四条预警；咪咪和豆豆正常。
2. **模拟器 → 自动 → 开始监测** —— 看重量曲线从 0 爬升到猫体重、如厕时出现阶跃下降、离场归零，摄像头画面切换并框出识别结果。
3. **模拟器 → 冲突样本 → 开始监测** —— 重量来自一只猫、画面来自另一只猫，系统会输出「身份未确认」而不是硬猜。这是整个 Demo 最值得看的一处设计。
4. **模拟器 → 上传照片** —— 传一张你自己的猫咪照片，看真实的画布特征提取与打分。
5. **记录** —— 点任意一条，查看这次判定的完整证据链。
6. **更多 → 逻辑自检** —— 17 条断言直接跑在页面里的真实算法上，不需要任何测试框架。

## 二、怎么发布成一条链接（GitHub Pages）

发出去之后别人在手机上点开就能用，免费、无需服务器、几乎不用维护。

**第 1 步**：在 [github.com/new](https://github.com/new) 建一个 **Public** 仓库，名字例如 `ulo-prism-demo`，**不要**勾选任何初始化文件。

**第 2 步**：本仓库**已经初始化并提交好了**（分支 `main`，工作区干净），所以你只要关联远程仓库并推送（把 `<你的用户名>` 换成你的 GitHub 用户名）：
```bash
git remote add origin https://github.com/<你的用户名>/ulo-prism-demo.git
git push -u origin main
```
推送时会弹窗让你登录 GitHub，登录一次即可。

> 提交作者目前是占位的 `ULO Demo`。想在提交记录里显示你自己的名字，先执行下面两行再推送（已经在本地提交过了，所以是改写这次提交）：
> ```bash
> git config user.name "你的名字"
> git config user.email "你的邮箱"
> git commit --amend --reset-author --no-edit
> ```

**第 3 步**：打开仓库的 `Settings → Pages`，把 **Source** 设为 `Deploy from a branch`，分支选 `main`、目录选 `/ (root)`，保存。

**第 4 步**：等 1 分钟左右，访问 `https://<你的用户名>.github.io/ulo-prism-demo/`，这就是可以发给别人的链接（建议用手机扫码或直接发微信打开验收一次）。

**以后要改内容**：改完文件执行 `git add -A && git commit -m "..." && git push`，1 分钟后线上自动更新。

> 不想用 GitHub：把整个文件夹拖到 [app.netlify.com/drop](https://app.netlify.com/drop) 也能立刻拿到一条链接。

## 三、复盘：怎么做的、花了多久、踩了什么坑

### 3.1 我是怎么做的

**Step 1 · 拆解题目。** 题目给了两个切口（多猫识别 / 如厕行为异常提醒）。我判断这两个不是二选一，而是同一条链路的两端：**识别是前提，行为记录是数据基础，健康预警是结论**。所以按"感知 → 识别 → 记录 → 分析"四层来搭，页面也按这四层组织。

**Step 2 · 定技术路线。** 要求是"点开链接就能用"，那就不能有后端、不能有构建步骤、不能依赖 CDN。最终选择：**纯静态 HTML/CSS/原生 JS + localStorage**，算法全部跑在浏览器里。这样 GitHub Pages 直接托管，零运维。

**Step 3 · 先写算法，再写界面。** 核心是两个模块：
- **识别打分**：重量特征用高斯函数算 `exp(-½·((实测体重−基线体重)/容差)²)`；图像特征把画面缩到 48×48，提取 12 维色相直方图 + 饱和度/明度/暗部占比/暖色占比 4 个标量，共 16 维向量，用直方图交集 + 标量相似度算吻合度。两者按 0.65 / 0.35 加权。
- **规则引擎**：按每只猫自己的基线算 7 日体重线性回归斜率、今日排尿次数、近 3 天久蹲次数等，触发 6 类预警并分 info / warn / alert 三级。

**Step 4 · 用确定性伪随机造数据。** 种子脚本按每只猫的基准体重生成 7 天记录，并且**埋了一条完整的异常线**：团子的体重每天下降约 1.9%、今天排尿 6 次（平时 3.3 次）、有两次久蹲到 2 分钟以上、最后一次尿量只有 10 g。因为是确定性随机，每次重置数据结果都一样，方便反复演示和写断言。

**Step 5 · 做实时模拟器。** 这是"演示感"的关键：不是放一张静态图，而是每 100 ms 采一个点，把"进入 → 稳定称重 → 如厕时重量阶跃下降 → 离场归零"整条曲线实时画出来，同时把抓拍帧、识别框、打分明细一起给出来。

**Step 6 · 内置自检。** 页面里放了一个 `#/selftest`，17 条断言直接跑真实算法（识别、规则、存储），分数不够就红。这样交付出去之后，别人（包括评委）可以自己验证逻辑不是"写死的假数据"。

### 3.3 踩过的坑

1. **`file://` 下 ES Module 会被 CORS 直接拦死。** 一开始用 `type="module"` 拆分模块，结果双击打开 HTML 时全部报错。改成传统 `<script>` + 全局命名空间，双击和线上都能跑。
2. **SVG 图片画进 canvas 会被判定为"污染"。** 本地 `file://` 下调用 `getImageData` 直接抛安全异常，图像特征整条链路崩掉。解决：`try/catch` 后降级成确定性的哈希特征向量，并把这个来源在页面上**明确标出来**；部署到 https 后自动恢复真实像素提取。
3. **余弦相似度根本区分不了猫咪。** 一开始图像相似度用余弦，三只猫两两算出来都是 0.95+ —— 因为直方图是非负向量，夹角天然很小。换成**直方图交集**（各自归一化后逐维取 min 求和）之后，三只猫两两相似度降到 0.30 / 0.38 / 0.34，区分度才出来。
4. **降级向量也踩了同一个坑。** 降级用的哈希向量是 16 个近似均匀分布的数，归一化后每条都长得差不多。改成"前 12 维用指数分布归一化"（模拟稀疏直方图）+ 后 4 维标量，形状才和真实特征对齐。
5. **"权重大的特征会掩盖矛盾证据"。** 冲突样本里，重量和图像指向不同的猫，但因为重量权重 0.65，加权总分依然是"重量那只"赢。最后加了一条**一致性规则**：当图像证据足够可信（≥0.6）且指向另一只猫时，直接判定"身份未确认"。这正是现实产品里避免误判的关键。
6. **滚动 24 小时窗口会把昨天的数据算进今天。** 用它做"排尿频繁"判断时，一只完全正常的猫在早上被测出"异常"。改成按自然日比较"今天 vs 之前几天日均"，并要求今天至少 4 次，误报才消失。
7. **手机端 `100vh` 会被浏览器工具栏吃掉。** 底部标签栏总是被 iPhone 的小黑条盖住。改用 `100dvh` + `env(safe-area-inset-bottom)`。
8. **无头浏览器截图差点骗了我。** 用 Edge headless 按 390px 截图，内容右侧被裁掉，看起来像布局溢出。实测 `window.innerWidth` 是 504 —— 是截图裁切假象。最后把页面塞进一个精确 390px 的 iframe 里才拿到可信的验收结果。
9. **浏览器直连大模型必然暴露密钥。** 纯静态页面没有后端可藏。所以真实大模型模式定位成"可选加分项"，默认走本地规则引擎，并在设置页明确写出这个限制。

### 3.4 已知局限

- 数据是合成的，不能用于任何真实的健康判断。
- 图像识别用的是通用颜色/轮廓特征，不是训练过的猫咪个体识别模型；真实产品需要先用每只猫自己的照片做定标。
- 规则阈值（例如每天下降 1.5%）取自常见兽医参考区间，需要在真实数据上重新标定。
- 真实大模型模式从浏览器直连，密钥对使用者可见，正式产品应改为服务端代理。

## 四、目录结构

```
index.html                 入口
assets/css/app.css         深色移动优先样式
assets/js/core.js          工具函数 / 图像特征 / 多猫识别 / 健康规则引擎 / 存储与合成数据
assets/js/sim.js           手写 SVG 图表 + 猫砂盆实时模拟器
assets/js/ai.js            AI 适配层（本地规则报告 / OpenAI 兼容视觉模型，失败自动降级）
assets/js/app.js           路由与全部视图（看板/模拟器/记录/猫档案/设置/实现说明/自检）
assets/img/*.svg           全部素材（手写 SVG，无外部依赖）
.nojekyll                  让 GitHub Pages 跳过 Jekyll 处理
```

## 五、可选的「真实 AI」模式

`更多 → AI 接入设置` 里可以切到真实视觉大模型：

- 接口地址：任何 **OpenAI 兼容**的 `/chat/completions`（例如 `https://api.openai.com/v1`）
- 模型名：需要支持图片输入，例如 `gpt-4o-mini`
- API Key：只保存在本机 `localStorage`，不会上传到任何第三方服务器

打开后，点「AI 生成分析」会把这次如厕的重量数据、这只猫的 7 日统计，以及摄像头抓拍帧一起发给模型，要求返回严格 JSON。**请求失败或网络不通时会自动降级回本地规则引擎**，不会白屏。

> 未填写 Key 时，一切都走本地规则引擎，功能完全可用 —— 评委不需要配置任何东西就能体验全部功能。
